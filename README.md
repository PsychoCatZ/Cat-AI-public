# CatAI

Личный ИИ-секретарь для Telegram через официальный Bot API и Connected Business Bots / Secretary Mode. Отвечает, пока владелец спит, честно представляется ИИ и ведёт свободный разговор через OpenAI API. Python 3.12+, без внешних runtime-зависимостей.

## Возможности

- `/sleep`, `/awake`, `/status` и постоянные кнопки в личном диалоге владельца с ботом. Управление защищено числовым OWNER_ID.
- Доступ только к личным чатам подключённого владельца. `CHAT_SCOPE=pilot` ограничивает одним TEST_CHAT_ID; `CHAT_SCOPE=telegram` использует чаты, разрешённые владельцем в Telegram.
- Проверка активного business-подключения, владельца, права can_reply и 24-часового окна перед отправкой. Telegram окончательно контролирует доступ к конкретному чату.
- Никаких методов удаления переписки, изменения профиля, финансовых операций или отметки прочтения. Подключения с лишними правами отклоняются.
- Отдельные контекст и согласие каждого собеседника. Дедупликация обновлений и сообщений в SQLite.

## Согласие и конфиденциальность

Первое сообщение — короткое представление и уведомление об использовании внешнего ИИ. До согласия текст разговора модели не передаётся.

- **Давай поболтаем** — после уведомления сохраняет согласие между сессиями и перезапусками.
- **Хватит** — отзывает согласие, очищает контекст и прекращает обычные ответы.
- **Очистить контекст** — очищает только контекст, сохраняя согласие.
- `/consent`, `/stop`, `/forget` — алиасы; `/hello` показывает приветствие.
- `/privacy` и `https://t.me/<BOT_USERNAME>?start=privacy` открывают политику без вызова модели. Зарегистрируйте команду privacy через BotFather `/setcommands` либо Bot API setMyCommands; собственный URL политики можно задать в настройках BotFather.

OWNER_USERNAME позволяет сделать фразы в приветствии ссылками, подставляющими текст в чат владельца. Нажатие ссылки само по себе не даёт согласия: требуется отправка сообщения.

Контекст — до 12 реплик в RAM, входящий текст до 4000 символов. Он очищается через час бездействия, при `/awake`, перезапуске и событиях изменения подключения/переписки. SQLite хранит только служебные идентификаторы, курсор обновлений, версию уведомления, дату/версию согласия и отказ. Ключи дедупликации удаляются через 7 суток при обработке новых событий. Вложения не скачиваются. Тексты и секреты в логи не записываются.

OpenAI получает инструкции и согласованный текст с ограниченным контекстом. Telegram ID и имена профилей отдельно не отправляются, но личная информация внутри текста автоматически не обезличивается. Используется store:false; это не гарантирует отсутствия технического хранения у провайдера. Перед собственным запуском изучите [правила OpenAI](https://developers.openai.com/api/docs/guides/your-data) и адаптируйте `src/catai/privacy.py` под свою эксплуатацию. Очистка контекста не удаляет уже обработанные провайдером данные или сообщения из Telegram.

## Установка и первый запуск

```sh
python3 -m venv .venv
.venv/bin/python -m pip install .
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

1. Создайте бота через BotFather, включите Secretary Mode. Начните личный диалог с ботом из аккаунта владельца.
2. Передайте процессу переменные из `.env.example`. Приложение само не загружает .env. Секреты вводите защищённо; не помещайте их в команды, логи или Git.
3. Сначала оставьте CHAT_SCOPE=pilot, задайте OWNER_ID и TEST_CHAT_ID, выберите только согласованный тестовый чат в Telegram. Разрешите ответы; права удаления, профиля, подарков, Stars и историй не выдавайте. Право can_read_messages не требуется.
4. После проверки конфигурации задайте RESPONSES_ENABLED=true. Запустите `catai`, отправьте `/status`, затем `/sleep` и новое сообщение от тестового собеседника.
5. Проверьте уведомление, согласие, память, отзыв, очистку, отключение ответов и паузу чата средствами Telegram.
6. После успешного пилота явно переключите CHAT_SCOPE=telegram. Доступными останутся только выбранные вами чаты Telegram; приложение не меняет этот список и не рассылает сообщения первым.

Образец конфигурации использует OpenAI `gpt-6-luna` через Chat Completions, reasoning_effort=none. Доступность модели и параметры проверяйте для своего API-проекта.

## VPS

Linux с systemd, Python 3.12+, исходящий HTTPS к Telegram и провайдеру модели. GPU, домен и входящие порты не нужны. Для небольшого личного использования начните с запаса 256 МБ RAM и 500 МБ диска; нагрузку измеряйте в своей среде.

`deploy/catai.service` предполагает код и venv в /opt/catai, отдельного пользователя catai и файл /etc/catai/catai.env с правами root:root 0600. StateDirectory создаёт /var/lib/catai. Unit ограничивает память 192 МБ, CPU 25% одного ядра, запрещает swap процесса и core dumps. Не меняйте общий swap сервера ради бота.

`deploy/configure.py` — вспомогательный интерактивный скрипт начальной настройки для root: вводит секреты через getpass, проверяет бота и webhook, сохраняет защищённый файл без перезаписи. Требует заранее установленной службы и пакета. Устанавливает пилот с выключенными автоответами; включение выполняется отдельно.

После установки службы:

```sh
systemctl daemon-reload
systemctl enable --now catai
systemctl status catai --no-pager
```

После каждого старта режим awake: владелец включает ответы кнопкой или /sleep. Запускайте один процесс на токен и БД. Существующий webhook вызывает отказ запуска и автоматически не удаляется.

## Ограничения

Обработка последовательная; во время сетевого запроса команда владельца может ждать его завершения. Для немедленного прекращения ответов приостановите чат или подключение в Telegram. Контекст соседних чатов изолирован, но события редактирования/удаления в текущей версии очищают весь RAM-контекст.

Дедупликация выполняется до внешних действий. При неоднозначном результате отправки повтора нет: возможен пропуск ответа, exactly-once доставка не гарантируется. Долговременная доступность и реальное окно Telegram требуют проверки в среде эксплуатации.

Запрет принимать обязательства и выдавать себя за человека задан инструкцией модели. У неё нет инструментов управления аккаунтом; ошибочные текстовые ответы всё равно возможны. Политика и документация — основа для собственного развёртывания, не обещание универсальной юридической применимости.
